# Decisions

Master log of architectural and product decisions for `jakpost_scraper`.
Each row records a decision, why it was made, and what was deliberately deferred.

| ID | Date | Topic | Decision | Rationale | Status | Backlog / Follow-up |
|----|------|-------|----------|-----------|--------|---------------------|
| D-001 | 2026-05-21 | Authenticated scraping — login method | Authenticate via a real browser (Playwright) rather than scripting login with raw HTTP. | Jakarta Post premium accounts use Google SSO (OAuth). Google's login runs JavaScript, captcha, and 2FA, which an `httpx`-only client cannot complete. | Superseded by D-007 | — |
| D-002 | 2026-05-21 | Session handling | Use a **persistent browser profile** (option A): first run opens a browser for one interactive Google login; later runs reuse the saved profile silently. Article fetching stays on the existing `httpx.Client`; Playwright is used only to obtain the session. | Minimizes recurring friction for non-technical users — login is a familiar one-time action, and most runs need zero interaction. Keeps the per-article scrape loop unchanged (no performance regression). | Superseded by D-007 | — |
| D-003 | 2026-05-21 | Performance impact of Playwright | Accept Playwright as a dependency. Browser launches **only** when no valid cached session exists; valid sessions load cookies straight into `httpx` with zero browser overhead. | Per-run cost is a one-time ~150 MB install plus ~2–5 s conditional startup. Per-article fetching is unaffected. Memory spike (~300–500 MB Chromium) is brief and released after auth. | Superseded by D-007 | — |
| D-004 | 2026-05-21 | Silent re-authentication | **Not pursued now.** Silent *reuse* of a valid session is supported; silent *re-auth* of an expired session is impossible with Google SSO (requires human 2FA). Re-auth, when needed, is automatic-to-trigger but interactive. | The scraper runs primarily as a manually triggered cron job. Sessions are evaluated at cold start and last days to weeks, so re-auth is rare. Not worth engineering further now. | Superseded by D-007 | — |
| D-005 | 2026-05-21 | Mid-run session expiry | If the session dies during a run, abort cleanly and re-prompt on the next run rather than silently shipping teaser text as full articles. | Failing loud prevents incomplete data being treated as complete. | Accepted | — |
| D-006 | 2026-05-21 | Startup session validation | **Deferred.** `ensure_session` returns cached cookies without a pre-flight validation request. An expired session is detected mid-run via the >50% truncated-rate signal (D-005). Also: persist **all** `thejakartapost.com` cookies rather than a hardcoded subset (auth spans `laravel_session` + `auth_token_tjp_new`, a Laravel backend whose cookie names may change). | Avoids choosing a stable known-premium URL now; news URLs are not durable. Acceptable because the scraper runs as a manually triggered cron job — a failed run is simply re-run after re-login. | Deferred | Revisit: add a startup validation check (needs a long-lived known-premium URL) if mid-run-only detection proves insufficient. |
| D-007 | 2026-05-21 | Authenticated scraping — login method (revised) | **Supersedes D-001/D-002/D-003/D-004.** Authenticate with a plain `httpx` HTTP flow against Jakarta Post's **native email/password login**, not Google SSO and not Playwright. `ensure_session` does: `GET /user/account/login` (in a fresh `httpx.Client` to receive `XSRF-TOKEN` + `laravel_session` cookies and scrape the hidden `_token` field) → `POST` the same form with `{_token, email, password}` → keep the resulting authenticated cookie jar. Credentials come from `JAKPOST_EMAIL` / `JAKPOST_PASSWORD` environment variables; nothing secret is written to the repo. Cookies are still cached to `auth_cookies_file` and reused without a startup validation request (D-006 still holds). | Inspection of the login page (2026-05-21) confirmed it is a standard Laravel HTML `<form method="POST">` with three inputs (`_token`, `email`, `password`), **no captcha**, and **no Cloudflare bot challenge** (the site is behind CloudFront, a plain CDN). This makes a browser unnecessary: drop the Playwright dependency, the `[auth]` extra, the `playwright install` step, and the persistent-profile logic. Login becomes fully non-interactive — ideal for an unattended cron job — and costs milliseconds, not seconds. | Accepted | The `_token` and `XSRF-TOKEN` cookie must originate from the **same** GET response (CloudFront may cache the login page); always GET immediately before POST within one client. Treat a CSRF/login failure as a clear, non-retryable `AuthError`. |
| D-008 | 2026-05-28 | Persistent run state (`state.json`) status | **Kept as-is.** `state.json` and the `state.py` module remain in active use on `main` and `feat/pip-install`: `load_state`/`save_state`/`prune_seen` are imported and called from [cli.py](jakpost_scraper/cli.py), `state_file` is a real config key in [config.py](jakpost_scraper/config.py), `--reset-state` deletes the file, and the on-disk `state.json` is updated each run. The installable-distribution spec ([2026-05-28-installable-distribution-design.md](docs/superpowers/specs/2026-05-28-installable-distribution-design.md)) therefore continues to include `state_file` in `platformdirs` path resolution. | A stateless-scraper refactor (commit `ec1ba48`) was made on the unmerged `feat/interactive-wizard` branch — it deletes `state.py`, drops `state_file`/`seen_url_retention_days`/`lookback_buffer_minutes` from config, and makes `--reset-state` a deprecated no-op. That work has not landed on `main` or `feat/pip-install`, so the live behavior is still stateful. Verified 2026-05-28 by reading branch tip code and `git branch --contains ec1ba48`. | Accepted | If/when `feat/interactive-wizard` is merged, revisit the install-distribution spec to remove `state_file` from the path-resolution section. |

## Notes

- "Status" values: **Accepted** (decided and in scope), **Deferred** (consciously parked, see follow-up), **Superseded** (replaced by a later decision — link the new ID).
- When a decision is revisited, add a new row rather than editing the old one, and mark the old row **Superseded**.
